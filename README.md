# xiaomi_qianbao_VIP

面向 **青龙面板（QingLong）** 的小米钱包每日任务脚本。

本项目基于 `kai648846760/xiaomiwallet` 的核心扫码登录与小米钱包任务逻辑进行青龙适配，增加：

- 青龙订阅自动生成任务
- 青龙 v2.17.12 兼容
- 一键扫码登录
- 多账号自动保存
- 多账号严格串行执行
- 登录凭证持久化
- 每日自动任务
- 青龙通知
- MI / VIP 日志 Banner
- 任务启动随机延迟
- 多账号间隔随机延迟
- 延迟环境变量自动创建

> 建议仅在自己的本地青龙环境中使用。自动化行为可能触发小米账号风控，请自行评估风险。

# 一、青龙最终会生成两个任务

成功拉取后，“定时任务”中应出现：

```text
ZzzHe_小米钱包扫码登录
ZzzHe_小米钱包每日任务
```

| 任务 | Cron | 用途 |
| --- | --- | --- |
| `ZzzHe_小米钱包扫码登录` | `0 0 29 2 *` | 手动运行，用于新增账号或刷新登录凭证 |
| `ZzzHe_小米钱包每日任务` | `37 8 * * *` | 每天 08:37 触发，随机延迟后执行 |

当前版本使用 JS 作为青龙任务入口：

```text
ZzzHe_xiaomi_wallet_daily.js
ZzzHe_xiaomi_wallet_login.js
```

再由 JS 从青龙仓库目录调用 Python 核心，因此兼容青龙 v2.17.12 只识别 JS 的场景。

# 四、环境变量 1：任务启动随机延迟

变量：

```text
ZzzHe2333_xiaomi_qianbao_VIP_suijiyanchi
```

第一次运行任务时，如果青龙不存在该变量，会自动创建：

```text
名称：ZzzHe2333_xiaomi_qianbao_VIP_suijiyanchi
值：30
备注：随机延迟
```

变量值记为 `A`，单位为 **分钟**。

要求：

```text
A 必须是正整数
1 <= A <= 360
```

非法值统一按：

```text
A = 30
```

实际随机等待：

```text
0.3 × A × 60 <= 实际睡眠秒数 <= A × 60
```

即：

```text
18A ～ 60A 秒
```

例如：

```text
A = 10
```

则实际随机等待：

```text
180 ～ 600 秒
```

默认 `A=30`：

```text
540 ～ 1800 秒
= 9 ～ 30 分钟
```

等待期间每约 30 秒打印一次当前时间、预计开始时间和剩余时间。

# 五、环境变量 2：多账号间隔延迟【重要】

新增变量：

```text
ZzzHe2333_xiaomi_qianbao_VIP_jiangeyanchi
```

第一次运行任意一个 `ZzzHe_...` 任务时，如果不存在，会自动创建：

```text
名称：ZzzHe2333_xiaomi_qianbao_VIP_jiangeyanchi
值：3
备注：多账号间隔延迟（分钟）
```

该变量值记为 `B`，单位为 **分钟**。

## B 的合法规则

必须同时满足：

```text
B 是正整数
1 <= B < 60
```

合法示例：

```text
1
2
3
10
30
59
```

非法示例：

```text
0
-1
1.5
abc
60
61
空值
```

只要不满足规则，本次运行统一按：

```text
B = 3
```

脚本不会擅自覆盖用户已经存在的非法变量，只是在本次执行中临时使用默认 `3`。

---

# 六、多账号间隔公式

多账号时，第一个账号 **完全执行结束** 后，才会计算账号间隔。

实际间隔秒数满足：

```text
0.5 × B × 60 <= 实际等待秒数 <= B × 60
```

即：

```text
30B ～ 60B 秒
```

## 示例：B = 3

```text
最短 = 0.5 × 3 × 60 = 90 秒
最长 = 3 × 60 = 180 秒
```

实际每次随机：

```text
90 ～ 180 秒
```

## 示例：B = 10

```text
300 ～ 600 秒
= 5 ～ 10 分钟
```

## 最大合法值：B = 59

```text
1770 ～ 3540 秒
= 29.5 ～ 59 分钟
```

`B=60` 已属于非法值，会回退为 `B=3`。

# 七、多账号严格串行模式

每日任务 **不会并发执行多个小米账号**。

执行顺序固定为：

```text
任务启动随机延迟 A
        ↓
账号 1 开始
        ↓
账号 1 完整执行钱包任务
        ↓
账号 1 完全结束
        ↓
随机等待 30B ～ 60B 秒
        ↓
账号 2 开始
        ↓
账号 2 完整执行钱包任务
        ↓
账号 2 完全结束
        ↓
随机等待 30B ～ 60B 秒
        ↓
账号 3
        ↓
...
```

也就是说：

**必须前一个账号执行结束，后一个账号才可能开始。**

即使前一个账号发生接口异常，也会先结束该账号处理流程，再进入账号间隔，然后处理下一个账号，不会同时请求多个账号。

每个账号执行完后还会立即写一次持久化配置，降低后续账号异常导致前面运行记录丢失的概率。

# 八、账号间等待日志

假设：

```text
B = 3
```

第一个账号执行完后可能看到：

```text
【多账号间隔延迟】
已完成账号：xiaomi_1
下一个账号：xiaomi_2
环境变量：ZzzHe2333_xiaomi_qianbao_VIP_jiangeyanchi
有效 B 值：3 分钟
随机范围：90-180 秒
本次等待：147 秒
预计下一个账号开始时间：2026-xx-xx xx:xx:xx
```

等待过程中每约 30 秒打印：

```text
⏳ 当前时间：2026-xx-xx xx:xx:xx | 下一个账号：xiaomi_2 | 预计开始：2026-xx-xx xx:xx:xx | 剩余约 117 秒
```

结束时：

```text
▶ 账号间隔结束，准备执行 xiaomi_2：2026-xx-xx xx:xx:xx
```

因此长时间等待时日志不会看起来像程序卡死。

# 九、多账号扫码登录

找到：

```text
ZzzHe_小米钱包扫码登录
```

运行后扫码。

当前版本已经支持自动多账号别名。

第一次扫码：

```text
xiaomi_1
```

第二次重新运行扫码任务并登录另一个小米账号：

```text
xiaomi_2
```

第三次：

```text
xiaomi_3
```

依此类推。

因此一般情况下 **不需要手动设置 `XIAOMI_WALLET_ALIAS`**。

只需要：

```text
运行扫码任务
→ 登录账号 1
→ 再次运行扫码任务
→ 登录账号 2
→ 再次运行扫码任务
→ 登录账号 3
```

脚本会自动选择下一个空闲的 `xiaomi_N`。

# 十、重复扫描同一个小米账号

如果没有手动设置 `XIAOMI_WALLET_ALIAS`，而你再次扫描了一个已经保存过的相同 `userId`，脚本会识别已有账号并刷新原凭证，不会故意再创建一个新的重复账号。

日志会提示类似：

```text
检测到该小米账号已存在，将刷新原账号别名：xiaomi_1
```

# 十一、手动指定/刷新账号别名

如果需要指定账号别名，或者刷新某个固定账号，可以设置：

```text
XIAOMI_WALLET_ALIAS
```

例如：

```text
XIAOMI_WALLET_ALIAS=xiaomi_2
```

然后运行：

```text
ZzzHe_小米钱包扫码登录
```

本次扫码结果会按指定别名保存/覆盖。

使用完后，如果希望恢复“自动分配下一个账号”，删除或禁用 `XIAOMI_WALLET_ALIAS` 即可。

# 十二、登录凭证保存位置

默认保存：

```text
/ql/data/config/xiaomi_qianbao_VIP/xiaomiconfig.json
```

每个账号保存：

```text
账号别名
userId
passToken
securityToken
更新时间
上次运行信息
```

凭证目录独立于 Git 仓库，因此正常更新订阅不会清除账号登录状态。

`passToken` 和 `securityToken` 属于敏感凭证，不要公开、发群、截图泄漏或提交到 Issue。

# 十三、每日任务

默认 Cron：

```cron
37 8 * * *
```

每天 08:37 由青龙触发。

完整流程：

```text
08:37 青龙触发
        ↓
读取 A
        ↓
随机等待 18A ～ 60A 秒
        ↓
读取所有已保存账号
        ↓
严格串行执行账号
        ↓
账号之间随机等待 30B ～ 60B 秒
        ↓
全部账号完成
        ↓
青龙通知
```

单账号时不会执行账号间隔等待。

# 十四、青龙通知

每日任务执行结束后会尝试调用青龙通知系统，复用你在青龙中已经配置的通知渠道。

关闭通知：

```text
XIAOMI_WALLET_NOTIFY=0
```

开启通知：

```text
XIAOMI_WALLET_NOTIFY=1
```

默认开启。

# 十五、两个延迟变量区别

| 环境变量 | 默认值 | 单位 | 作用 | 合法范围 |
| --- | ---: | --- | --- | --- |
| `ZzzHe2333_xiaomi_qianbao_VIP_suijiyanchi` | `30` | 分钟 | 整个任务刚启动时随机延迟 | `1-360` 正整数 |
| `ZzzHe2333_xiaomi_qianbao_VIP_jiangeyanchi` | `3` | 分钟 | 多账号之间的随机间隔 | `1-59` 正整数 |

不要混淆：

```text
suijiyanchi
= 整个任务启动前延迟

jiangeyanchi
= 账号 1 → 账号 2 → 账号 3 之间的延迟
```
